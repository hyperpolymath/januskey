== PROOF-NEEDS.md — januskey

=== One ABI tree (2026-10-12)

The Idris2 ABI surface was three trees: the flat sources in `+src/abi/+`,
the `+src/idris-abi/+` symlink farm added by PR #140 so that an `+.ipkg+`
could reach them, and `+generated/idrisiser/+`. It is now one: the sources
live at `+src/abi/JanusKey/ABI/{Types,Layout,Foreign,Proofs}.idr+`, laid out
by module name, with the package file beside them at
`+src/abi/januskey-abi.ipkg+`; the symlink farm is deleted; the
`+Januskey.ABI.Foreign+` / `+JanusKey.ABI.*+` casing split (J1-3) is
normalised to `+JanusKey+`. `+scripts/check-abi-tree.sh+` (`+just
abi-tree-check+`, first step of `+idris-abi.yml+`) fails on a second package
file, a second `+Foreign.idr+`, a symlink under `+src/abi+`, a module whose
declared name differs from its path, or a package/file mismatch.

What this commit does *not* claim: the package still does not typecheck.
Two facts were established while relocating it and are the next two
commits, not this one:

* `+Foreign.idr+` is the RSR *template* FFI (`+januskey_init+`,
  `+januskey_process+`, `+januskey_get_string+`, …) written against
  template types (`+createHandle+`, `+handlePtr+`, `+Result+`) that the
  hand-written `+Types.idr+` does not define. It never described
  `+ffi/zig+`, which exports `+jk_init+` … `+jk_version+` against
  `+ffi/zig/include/januskey.h+`; that header's former comment
  "generated from src/abi/Foreign.idr" was false and has been corrected.
* `+Types.idr+` has the ten known errors from PR #140 (first:
  `+isInfixOf+` without `+import Data.String+`; also forward references in
  `+ResultOf+`, a `+Handle+` whose only constructor cannot inhabit
  `+Handle Locked+`, linear variables used twice or not at all, and
  `+oblitMostExpensive (S k) = Oh+` on an open `+k+`).

`+generated/idrisiser/+` was left outside the gate here; the owner decided
(2026-10-14) to remove it, with its `+idrisiser/*.tsig+` inputs and
`+idrisiser.toml+`. `+scripts/check-abi-tree.sh+` now fails if any of them returns.

Removed, with the reason recorded beside the replacement in source:
`+memoryDefeatsGPU+`, `+timeCostMonotonic+`, `+outputIs256Bits+`,
`+threePassMinimum+` (closed literals or restated hypotheses);
`+defaultExceedsMinimum+`, `+defaultMeetsOWASP+`, `+defaultMemoryOWASP+`
(restated record fields that already carry the bound); `+cnoPairCompose+`,
`+tamperDetectable+` (returned Unit); `+identityIsCNO+` (`+s = s+`);
`+hashOneWay+` (`+Void -> Void+`); `+canRollback+` (returned its argument);
`+copyDeleteCNO+` (no body, false as stated); `+linearFileConsumed+`
(ill-typed; claimed `+LinearFile -> Void+`); `+systemForgetsOldKey+`
("forgets" has no negative form in the Knows model);
`+revokedKeyUnusable+` (`+adversaryCannotKnow+` at `+KeyId+`; took no
revocation); `+errorCodeDeterministic+` over an undefined `+CError+` (now
`+statusCodeInjective+`).

Model limits, stated so no reader over-counts them: `+Knows Adversary a+`
being uninhabited is a modelling choice, not a security proof; `+FSState+`
tracks (path, hash) pairs, not contents, so C-2 is about the operation log;
linearity is a property of the binding — a handle bound by an IO `+<-+` is
unrestricted, the guarantee holds for `+(1 h : LibHandle Open)+` parameters,
and plain IO's bind is not linear, so such a handle cannot be closed inside
IO do-notation at all.

The dashboards (README, TOPOLOGY, READINESS) carry the proof count that
`+dashboard-check+` measures from the PROVEN rows of the ledger below.

=== Recommended Prover

*Agda* (`+--safe --without-K+`) is the proof kernel and *Idris2* the
ABI/runtime layer (ruling 2026-10-12): kernel statements live in
`+verification/proofs/agda/+` with siblings consumed by pin
(`+scripts/fetch-siblings.sh+`); the ABI lives in `+src/abi/+`.
Transaction atomicity is stated there for the model
(`+verification/proofs/agda/TransactionAtomicity.agda+`, rows T-1 to T-3; the Rust fixes behind T-4 and T-5 are tested, not proved);
obliteration completeness and attestation chain integrity are still to be stated. The 225 `+unwrap()+` calls should
be systematically replaced with proven error handling.

=== Priority

*HIGH* — JanusKey handles cryptographic key management, attestation
chains, and data obliteration. Any correctness bug in obliteration or
key derivation is a critical security vulnerability. The ABI layer now
typechecks, but none of the security obligations above is proved.
