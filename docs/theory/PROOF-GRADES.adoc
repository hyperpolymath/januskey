= Proof grades under mathesis and PROOF-POLICY
:toc: preamble
:icons: font

This page grades januskey's proof claims in the vocabulary its owner's estate
mathematics architecture uses, and records the receipt for every grade. It is
the answer to a single question a reader of `PROOF-NEEDS.adoc` should not have
to reconstruct: *which of these claims is a proof, and how good a proof is it?*

It grades nothing by confidence. There is no percentage anywhere in this
repository, and none is introduced here.

== What governs the grades

Two owner documents, both read at HEAD on 2026-11-01:

[cols="1,2,3",options="header"]
|===
| Source | Section | Rule taken from it

| `hyperpolymath/mathesis`,
  file `estate-mathematical-architecture`
| §5 grades
| **Grade 3** — "a proof is Grade 3 if it type-checks locally in Agda but has
  not been translated to an independent foundational system". Grade 2i adds one
  translation, Grade 2ii two *foundationally distinct* ones (Agda, Rocq and
  Lean are all dependent type theory, so 2ii needs Isabelle/HOL), Grade 1 is a
  check served to headless CI tooling (AXLE, isabelle server, coq-lsp REST).

| mathesis, same file
| §6 reporting
| No percentage; every axiom the development relies on is tracked; a grade
  receipt records the **commit hash** it was produced at; a grade that stops
  applying is marked `Superseded` or `Regressed`, never quietly deleted.

| `hyperpolymath/standards`,
  `3-practice/PROOF-POLICY.adoc`
| §1 mapping
| Theory is proved in **Agda** and rechecked in Rocq and Lean; the behaviour of
  first-party Rust is **Creusot** on that code; API, ABI and wire-format
  contracts are **Idris2**. The earlier "Rust always means Rust/SPARK" note is
  withdrawn (owner ruling 2026-04-10): Rust is Creusot.

| PROOF-POLICY
| §2.1 invocation
| `agda --safe --without-K --cubical-compatible <module.agda>`; pin and record
  the Agda version and the library set per commit; a missing tool is an open
  obligation, never a silent skip.

| PROOF-POLICY
| §2.3 execution
| The policy text records policy; CI receipts establish the executions. §2.2's
  statuses (`AGDA-PENDING`, `AGDA-VERIFIED`, `COQ-CHECKED`, `LEAN-CHECKED`,
  `BRIDGE-PENDING`, `RECONCILED`, `COUNTEREXAMPLE`, `QUARANTINED`) name what
  happened to one proposition.
|===

januskey's own five-status ledger vocabulary (`PROVEN`, `TESTED`, `ASSUMED`,
`DESIGNED`, `OPEN`) is the estate's claim vocabulary and is unchanged by any of
this. A grade is a second axis laid over it, not a replacement: a row is
`PROVEN` *because* a named artefact checks it, and separately has (or has not) a
mathesis grade.

== The Grade 3 receipt

The theory artefacts are two Agda modules:

* `verification/proofs/agda/Reversibility.agda` — the Loss grade algebra:
  lossless traces have only lossless steps, obliteration absorbs, and a
  wrap/unwrap pair with a cancellation premise is a grade-𝟙 two-step trace.
* `verification/proofs/agda/TransactionAtomicity.agda` — rollback restores the
  state the transaction began in; the `TransactionManager` lifecycle keeps its
  log invariant under begin, add_operation, commit and mark_rolled_back, and at
  most one transaction is Active.

Both are checked by `scripts/check-agda.sh` (`just test-agda`), which is also
the ledger's recorded checker for rows G-1, T-1, T-2 and T-3. The receipt:

That is a Grade 3 receipt in mathesis terms: the propositions type-check in
Agda, in CI, at a named commit, with the prover version pinned and recorded.
mathesis §5 illustrates "strict solver flags" with `--safe --erasure`;
januskey's strictness is `--safe --without-K` plus `--double-check`, which is
the same family and stricter than bare `--safe` (no K, no trusted compiled
interfaces, a second checking pass).
Nothing here has been translated to Rocq, Lean or Isabelle, so it is not
Grade 2i, and no headless proof service is involved, so it is not Grade 1.

=== Why it stops at Grade 3

Grade 2i and above would require an Agda → Dedukti → Rocq/Lean transport or a
re-proof, with the outcome recorded as `transported`, `re-proved` or
`unavailable` (PROOF-POLICY §2). That work has not been done, is not claimed,
and would not change what these modules prove: §2.2 is explicit that compiling
in a second prover does not establish the same proposition unless the
correspondence is checked too.

== The §2.1 invocation: adopted, and measured (2026-11-01)

PROOF-POLICY §2.1's canonical form is
`agda --safe --without-K --cubical-compatible <module.agda>`. Until this branch
the gate ran `--safe --without-K --no-libraries --ignore-interfaces
--double-check` without the cubical flag, and an earlier revision of this page
predicted that adding it would fail, because the flag is *infectious* (direct
imports must use it too) and every module of the pinned sibling opens with
`{-# OPTIONS --safe --without-K #-}`.

**That prediction was wrong and is withdrawn.** With Agda 2.6.4.3 installed in
the sandbox (PyPI wheel `agda==2.6.4.3.post1`, reporting
`Agda version 2.6.4.3-56f5f56`, the same version CI pins), the canonical
invocation type-checks both modules:

[source,text]
----
$ agda --safe --without-K --cubical-compatible --no-libraries \
       --ignore-interfaces --double-check \
       -i verification/proofs/agda -i _build/dependencies/resource-algebra/src \
       verification/proofs/agda/Reversibility.agda
   → exit 0, 14 × warning: -W[no]UnsupportedIndexedMatch

$ … verification/proofs/agda/TransactionAtomicity.agda
   → exit 0, 16 × warning: -W[no]UnsupportedIndexedMatch

$ AGDA=/tmp/tc/bin/agda bash scripts/check-agda.sh
   → [PASS] refused as expected: tests/reject-agda/{CommitWhenIdle,ForwardRollback,HiddenLoss,ReviveAfterObliterate}
   → [check-agda] OK
----

Agda warns where the earlier reading expected it to refuse: a `--without-K`
import is accepted, and what it reports is that particular clauses — the
sibling's `≤-trans`, and `obliterate-absorbs` here — will not compute when
applied to cubical transports. That is a statement about computation under
transport, not about the propositions these modules prove, so the gate keeps the
warnings visible rather than silencing them with `-WnoUnsupportedIndexedMatch`.

`scripts/check-agda.sh` now runs the canonical invocation, so januskey matches
§2.1 exactly and is still stricter in two other respects (`--ignore-interfaces`
re-checks the sibling from source instead of trusting compiled interfaces;
`--double-check` re-verifies the type-checker's own work).

=== Receipt bookkeeping for that change

The CI receipt in the table above was produced **before** the flag changed.
Changing a graded artefact's checker invalidates its receipt's exactness, so:

* the local run above is recorded as **reproduction** — same prover version,
  PyPI provenance instead of Debian, and no CI provenance at all (PROOF-POLICY
  §2.3: receipts of execution come from CI);
* the next `agda-proofs.yml` run on `main` is the new receipt, and this page
  must cite it in place of the local run once it exists. Until then the rows
  stay `AGDA-VERIFIED` on the strength of the four artefacts being unchanged
  plus a matching local run, and that is the strongest claim available.

One related inconsistency is an open obligation, not a claim: the Agda version
is pinned twice in CI and the two pins differ — `agda-proofs.yml` installs
2.6.4.3 (the receipt above), while `dashboard-check.yml` installs 2.6.3 on the
Idris2 image so it can run the PROVEN rows' checkers. A green dashboard
therefore does not extend the receipt at 2.6.4.3. One version, one receipt:
pinning the dashboard job to the same Agda is the fix.

=== Upgrade path, measured

`agda==2.7.0.1` runs in the sandbox once its wheel's missing `data/lib` is
supplied (bare install dies with "The lib directory … does not exist"), and
under 2.7.0.1 **both modules also type-check, exit 0**. The latest upstream
release is 2.8.0.2 (2026-09-13), which has not been tried. None of this is a
recommendation to move: the CI pin is Debian trixie's 2.6.4.3, and an upgrade
means a new container, a new pin and a new receipt.

The sandbox's installable set, and the exact hosts that block Rust, Creusot and
Idris2, are recorded in `docs/estate/environment-toolchains.md`.

== Grades, ledger row by ledger row

The 46 ledger rows fall into three classes under PROOF-POLICY §1. Counts are
from `PROOF-NEEDS.adoc` at this commit and are `PROVEN` 11, `TESTED` 23,
`ASSUMED` 4, `DESIGNED` 3, `OPEN` 5.

=== Grade 3 — theory, proved in Agda

[cols="1,3,2",options="header"]
|===
| Row | Proposition | Theorem

| G-1 | A lossless trace has only lossless steps; an obliterating step absorbs;
  wrap/unwrap is grade 𝟙 given cancellation | `Reversibility.agda::lossless-trace-all`,
  `obliterate-absorbs`, `wrap-unwrap-id`
| T-1 | Undoing a fully executed transaction in reverse order restores the state
  it began in, given each step's undo restores its execute |
  `TransactionAtomicity.agda::rollback-restores`
| T-2 | The four lifecycle transitions preserve the log invariant and rewrite
  only the Active transaction | `TransactionAtomicity.agda::lifecycle-preserves-good`
| T-3 | At most one transaction is Active, exactly one when the pointer is set |
  `TransactionAtomicity.agda::at-most-one-active`
|===

These four are the only rows in this repository with a mathesis grade. Each
rests on a premise it names rather than assumes silently — the per-step
cancellation law (`undoes`, TESTED as `execute_then_undo_is_identity`), the
freshness of the transaction id (T-7, `ASSUMED`, probabilistic), and the
absence of I/O. §6 asks for the axioms to be tracked; they are, in the modules'
own "What is NOT claimed" blocks and in the ledger's T-6, T-7, G-2, X-1 rows.

=== Engineering contracts — no mathesis grade applies

Seven `PROVEN` rows are Idris2 theorems about this ABI: A-1, A-2, C-1, C-2,
C-3, C-4, C-5, checked by
`idris2 --typecheck src/abi/januskey-abi.ipkg`. Under PROOF-POLICY §1 these
are interface and wire-format contracts, so the theory ladder does not grade
them — they are `PROVEN` in the ledger's own vocabulary and that is the whole
of the claim. The `Rust/SPARK` shorthand is withdrawn; the mapping that
replaces it is Rust → **Creusot**, Ada → SPARK, API/ABI → Idris2, theory →
Agda.

The same heading covers every `TESTED` row (23): a test proves behaviour was
observed, never that it always holds. G-2 (the Idris2 ↔ Agda correspondence) is
`ASSUMED` by transcription and would have to become mechanical before any
"every operation is reversible" theorem could cite both halves.

== Reporting rules this repository follows

* No percentage, ever. Where a "completion" figure exists elsewhere in the
  tree it is a project-plan measure, not a proof measure, and it is not a grade.
* Every grade names its receipt: commit, prover, prover version, flags,
  sibling pin. The receipt above is the only one of its kind here.
* A receipt is invalidated by a change to a graded artefact, to its checker or
  to its pin, and is then re-earned by the next run, not carried forward. The
  blob comparison in §The Grade 3 receipt exists precisely to show which
  changes do and do not invalidate it.
* When a graded artefact is replaced, the grade is marked `Superseded`; when a
  green receipt goes red and is not immediately fixed, `Regressed`. Neither is
  deleted from the history.
* `AGDA-PENDING` is the correct status for a module committed but not yet
  checked. No row in this repository is in that state today: the four graded
  rows are `AGDA-VERIFIED` at the commit above.
