= Proof Witness Grades (PROOF-POLICY §8)
:toc: preamble
:icons: font

This page grades januskey's proof claims in the vocabulary its owner's estate
mathematics architecture uses, and records the receipt for every grade. It is
the answer to a single question a reader of `PROOF-NEEDS.adoc` should not have
to reconstruct: *which of these claims is a proof, and how good a proof is it?*

It grades nothing by confidence. There is no percentage anywhere in this
repository, and none is introduced here.

[NOTE]
====
*PWG census, theory theorems of this repository (denominator 5):*
`PWG-2ii` 5 (G-1, T-1, T-2, T-3, E-1m), receipt pending · `PWG-3` 0 ·
`PWG-2i` 0 · `PWG-1` 0 · `ungraded` 0. `+foundation-diverse`: none. Axioms:
none, in any of the three provers.

The denominator is the ledger rows whose source of truth is an Agda theorem.
PROOF-POLICY §1 puts a statement that names one repository's type, function or
wire format in engineering, so these rows are outside it: G-3 (the FFI bridge
preserves grade 𝟙, `OPEN`), E-1 (a security property of the implementation; its
model half is E-1m), the MPR row (a refinement claim about Rust, which §1 sends
to Creusot and Verus) and G-2 (a bridge, `ASSUMED`). By the same test, T-2
and T-3 used to be stated over a hand-transcribed model of this repository's
`TransactionManager`. On the owner's ruling of 2026-11-09 they were split. The
theorems now live in `SingleActiveLog.agda`, over any record type with a key and
an active or settled phase: theory, in the census. The claim that januskey's
Rust refines that log is the new engineering row T-10 (`OPEN`, for Creusot or
Verus).

== The receipts

The theory artefacts are four Agda modules:

* `verification/proofs/agda/Reversibility.agda` — the Loss grade algebra:
  lossless traces have only lossless steps, obliteration absorbs, and a
  wrap/unwrap pair with a cancellation premise is a grade-𝟙 two-step trace
  (G-1).
* `verification/proofs/agda/TransactionAtomicity.agda` — rollback restores the
  state the transaction began in (T-1), and januskey's `TransactionManager`
  lifecycle as an instance of the single-active log.
* `verification/proofs/agda/SingleActiveLog.agda` — the single-active log as
  theory: the transitions keep the invariant, and at most one record is active
  (T-2, T-3).
* `verification/proofs/agda/Epistemic.agda` — the model-level half of E-1
  (row E-1m, §The epistemic rewrite below).

All four are checked by `scripts/check-agda.sh` (`just test-agda`), which is
the ledger's recorded checker for rows G-1, T-1, T-2, T-3 and E-1m. Their Rocq
and Lean legs are checked by `scripts/check-recheck.sh` (`just test-recheck`).
Both run in `agda-proofs.yml`, as two jobs of one workflow.

The receipt of record for all five rows' legs is the job "Rocq and Lean recheck
legs, expected rejections" of the same run as §The Agda receipt. T-1's legs
were first checked on `main` at `0834ce7` (run 42646851111 above), with the gate

`PWG-2ii`, *receipt pending*: the legs check locally and on the pull request,
which is evidence, not a receipt (PROOF-POLICY §2.3).

Those are the facts the grades rest on. The Agda propositions type-check under
the §2.1 invocation, in CI, at a named commit, with the prover version pinned and
the import cone recorded: that is `PWG-3`. Each of the five rows also has a Rocq

makes it `PWG-2ii`. No witness in another foundation exists, so
`foundation_diverse` is false throughout. `PWG-1` would also need current
receipts on every commit for every counted witness, which nothing here records
yet.

== The §2.1 invocation: adopted, and measured (2026-11-01)

PROOF-POLICY §2.1's canonical form is
`agda --safe --without-K --cubical-compatible <module.agda>`. Until this branch
the gate ran `--safe --without-K --no-libraries --ignore-interfaces
--double-check` without the cubical flag, and an earlier revision of this page
predicted that adding it would fail, because the flag is *infectious* (direct
imports must use it too) and every module of the pinned sibling opens with
`{-# OPTIONS --safe --without-K #-}`.

**That prediction was wrong and is withdrawn.** With Agda 2.6.4.3 installed in
the sandbox (PyPI wheel `agda==2.6.4.3.post1`, reporting
`Agda version 2.6.4.3-56f5f56`, the same version CI pins), the canonical
invocation type-checks both modules:

[source,text]
----
$ agda --safe --without-K --cubical-compatible --no-libraries \
       --ignore-interfaces --double-check \
       -i verification/proofs/agda -i _build/dependencies/resource-algebra/src \
       verification/proofs/agda/Reversibility.agda
   → exit 0, 14 × warning: -W[no]UnsupportedIndexedMatch

$ … verification/proofs/agda/TransactionAtomicity.agda
   → exit 0, 16 × warning: -W[no]UnsupportedIndexedMatch

$ AGDA=/tmp/tc/bin/agda bash scripts/check-agda.sh
   → [PASS] refused as expected: tests/reject-agda/{CommitWhenIdle,ForwardRollback,HiddenLoss,ReviveAfterObliterate}
   → [check-agda] OK
----

Agda warns where the earlier reading expected it to refuse: a `--without-K`
import is accepted, and what it reports is that particular clauses — the
sibling's `≤-trans`, and `obliterate-absorbs` here — will not compute when
applied to cubical transports. That is a statement about computation under
transport, not about the propositions these modules prove, so the gate keeps the
warnings visible rather than silencing them with `-WnoUnsupportedIndexedMatch`.

`scripts/check-agda.sh` now runs the canonical invocation, so januskey matches
§2.1 exactly and is still stricter in two other respects (`--ignore-interfaces`
re-checks the sibling from source instead of trusting compiled interfaces;
`--double-check` re-verifies the type-checker's own work).

=== Receipt bookkeeping for that change

The local run above is recorded as **reproduction** only: same prover version,
PyPI provenance instead of Debian, and no CI provenance (PROOF-POLICY §2.3:
receipts of execution come from CI). The CI receipt it was waiting for was run
42076969251, the first to run the canonical invocation on all three modules. It
is now itself `superseded` (§The Agda receipt), as are the receipts from before
the flag changed.

One related inconsistency is an open obligation, not a claim: the Agda version
is pinned twice in CI and the two pins differ — `agda-proofs.yml` installs
2.6.4.3 (the receipt above), while `dashboard-check.yml` installs 2.6.3 on the
Idris2 image so it can run the PROVEN rows' checkers. A green dashboard
therefore does not extend the receipt at 2.6.4.3. One version, one receipt:
pinning the dashboard job to the same Agda is the fix.

=== Upgrade path, measured

`agda==2.7.0.1` runs in the sandbox once its wheel's missing `data/lib` is
supplied (bare install dies with "The lib directory … does not exist"), and
under 2.7.0.1 **both modules also type-check, exit 0**. The latest upstream
release is 2.8.0.2 (2026-09-13), which has not been tried. None of this is a
recommendation to move: the CI pin is Debian trixie's 2.6.4.3, and an upgrade
means a new container, a new pin and a new receipt.

The sandbox's installable set, and the exact hosts that block Rust, Creusot and
Idris2, are recorded in `docs/estate/environment-toolchains.md`.

==== The recheck legs (T-1 2026-11-09, then G-1, T-2, T-3 and E-1m)

T-1 was the pilot, chosen because its statement is small and abstract. The other
four followed the same route.

*Why re-proved.* §2 asks for transport first. The Agda → Dedukti translator
(`Deducteam/Agda2Dedukti`, last changed 2022-01-24 at `c7c7d67`) builds against
a forked Agda branch of that period and its documentation pins Lambdapi 2.1.0.
It cannot read modules checked by the pinned Agda 2.6.4.3, so no transport
route exists for this toolchain. For Lean, §2 already says to re-prove until a
released Lambdapi has a Lean exporter. Every leg is therefore re-proved by
hand, in each prover's core library: no Mathlib and no imports in the Lean
legs, and only the prelude in the Rocq legs.

*The statements, side by side.* Each leg restates every theorem the row cites,
and the lemmas they rest on, under the same name in each prover's identifier
syntax (`-` becomes `_`, `𝟙` becomes `one`, `++` becomes `app`).

For example, T-1 in all three:

[cols="1,3",options="header"]
|===
| Prover | Proposition

| Agda
| `rollback-restores : ∀ {os x z} → Executed os x z → rollback os z ≡ x`

| Rocq

  Executed os x z -> rollback os z = x`

| Lean
| `rollback_restores {S : Type} {os : List (Op S)} {x z : S} :
  Executed os x z → rollback os z = x`

*How the comparison was made.* By reading, definition by definition. It was not
done by a round trip, since no translator exists.

* *Common to all.* Agda's builtin `List`, `Maybe`, `Nat` and `Bool` and the
  targets' `list`/`option`/`nat`/`bool` and `List`/`Option`/`Nat`/`Bool` are
  the same free inductive types. Each module parameter in `Set` is a `Type`
  parameter (level 0) in the targets: Rocq's `Section` variables and Lean's
  `variable`s become arguments of every theorem that uses them, as an Agda
  module parameter does when the theorem is used from outside.
* *T-1.* `Op` is a record of `execute : S → Maybe S`, `undo : S → S` and
  `undoes : execute x ≡ just y → undo y ≡ x`. The targets have the same three
  fields over `option`/`Option`. Agda binds `x` and `y` implicitly and Rocq
  explicitly, which is the same proposition. `Executed` is an inductive family
  in `Set` with constructors `done` and `next`; the targets put it in `Type`,
  the same level, with the same constructors and indices. `rollback` is the
  same structural recursion, undoing the head after the tail. The sibling's
  prelude: `_≡_` is `Agda.Builtin.Equality` re-exported, and `trans` and
  `cong` are the usual one-clause definitions by matching on `refl`. Rocq's
  `eq` with `eq_trans`/`f_equal`, and Lean's `Eq` with `Eq.trans`/`congrArg`,
  are the same inductive equality and the same eliminations. The re-proofs use
  `rewrite`, which needs nothing beyond the equality type. No other sibling
  definition reaches T-1's statement or proof.
* *T-2 and T-3.* The log is parameterised the same way in all three: a record
  type `R`, a key type `I`, decidable key equality, `key` and `phase`. The
  decision procedure returns Agda's `(a ≡ b) ⊎ (a ≢ b)`, Rocq's
  `{a = b} + {a <> b}` and Lean's `PSum (a = b) (a ≠ b)`, the same sum of the
  same two propositions. `update`, `begin`, `modify` and `finish` have the same
  clauses, matching on the log's pointer as Agda does. `Good` has the same two
  constructors with the same premises. Lean writes `Settled` and `Fresh`
  unfolded (`phase u = settled`, `key u ≠ i`), which are their definitions.
  `countActive` adds one with `suc` in Agda and Rocq and with `+ 1` in Lean,
  the same number by definition.
* *G-1.* The legs cannot import `resource-algebra`, so they restate what G-1
  uses of `ResourceAlgebra.Instances.Loss` at `cf9235c`: the carrier
  `Grade = fin Nat | inf`, the sequence product `_+g_` with its three clauses,
  its left unit and both annihilation laws. The alternatives operation `_⊓g_`
  and the dioid laws are not used by G-1 and are not restated. `Step`,
  `Trace` (its own datatype in all three, not a list), `AllLossless`,
  `Contains`, `Obliterating` and `ReversiblePair` have the same fields and
  constructors. `wrapStep` and `unwrapStep` *assign* grade `fin 0`, as in the
  Agda, so `wrap-unwrap-𝟙` holds by computation in all three and does not use
  `cancels`. Rocq names the trace constructors `tnil`/`tcons` and the pair
  constructor `mkPair`, because its prelude already has `pair`.
* *E-1m.* `_==_` on `Nat` has the same four clauses. Agda's `if_then_else_` is
  its own function on `Bool`. Rocq's `if` on a `bool` is the same match, and
  Lean's leg defines `ite'` by matching, since Lean's `if` decides a `Prop`, a
  different construct. `World` has the same three fields, and `Knows`,
  `CanUse`, `x₁`, `x₂`, `obliterate` and `rotate` the same definitions. Agda's
  record update becomes a full constructor with the unchanged fields copied.
  `Recovers` is a `Σ` in `Set`; the targets use `sigT` and `PSigma` in `Type`.
  `¬ Recovers …` is written `Recovers … → False`, which is its definition.

*Residual differences, listed rather than hidden.*

* *Equality.* Axiom-free Rocq has neither K nor uniqueness of identity proofs,
  like Agda under `--without-K`, and `Print Assumptions` confirms that no leg
  adds an axiom that would supply them. Lean is stronger: its `Eq` lives in a
  proof-irrelevant `Prop`, so it has uniqueness of identity proofs
  definitionally. No proof uses it: each leg proves its statements by the same
  inductions and case splits as the Agda.
* *Where the invariants live.* Agda puts `Good`, `All`, `AllLossless` and
  `Contains` in `Set`, as proof-relevant data. The targets put them in `Prop`
  (`Executed` stays in `Type`, because `rollback` is defined over the list, not
  over the derivation). No restated theorem eliminates one of these predicates
  into data: each concludes another predicate or an equation, so the placement
  removes nothing the statements use.
* *Arithmetic.* Lean's `Nat.add` recurses on its second argument, Agda's and
  Rocq's on the first. So `fin 0 +g a ≡ a` holds by computation in Agda and
  Rocq and by the lemma `Nat.zero_add` in Lean, which reports no axioms.
* *Axioms in Lean's core library.* `Nat.succ_ne_zero`, and `nomatch` on two
  different numerals, depend on `propext` in Lean 4.35.0. The legs use neither
  (`Nat.noConfusion`, and comparison by `==`), so the axiom report stays empty.
  The axiom report caught both while the legs were being written.

*Axioms.* Each leg ends with one `Print Assumptions` (Rocq) or `#print axioms`
(Lean) for each theorem the row cites and each refusal lemma: 22 in Rocq and 22
in Lean. A report covers every lemma the theorem uses. Every one reports "Closed under the global context" or "does not depend on any
axioms". The gate (`scripts/check-recheck.sh`) counts them and fails unless
every report is clean, so a file with several theorems cannot pass on the
strength of one. Mutants with `Admitted` on `modify_good` in Rocq and with
`sorry` on `finish_good` in Lean each fail it ("6 of 7"), and so do the same
mutants on the refusal lemma `modify_refused_when_idle`. Before that change
the gate looked for one clean line per file, which was enough while each file
held one theorem.

== The epistemic rewrite: E-1 becomes E-1m

The one claim with an inheritance, rather than an invention, behind it. januskey's
Idris2 ABI carries `Knows : Agent → Type → Type` (`Types.idr` §Level 12), a
discrete epistemic modality inherited from the estate's epistemic-types work. It
could not state the security claims the ledger attributed to it:

* `Knows Adversary a` is uninhabited **by construction** — there is no Adversary
  constructor — so "an attacker cannot recover …" (E-1) was a property of a
  datatype. The repository's own comment says as much: "a property of this
  model, not a security proof".
* "The system forgets the old key" was **unstateable**, because `Knows` has no
  negative form. The lemma was deleted rather than repaired, and the ledger
  records the deletion.

`verification/proofs/agda/Epistemic.agda` replaces the modality with one whose
ignorance is a proposition. Knowledge is indiscriminability over an observation
— an agent knows φ in *x* when φ holds in every world it cannot tell apart from
*x* — so:

* ignorance is `¬ Knows`, proved by exhibiting a world that looks the same and is
  not (`adversary-ignorant`, over two worlds that differ only in the store);
* obliteration is a change to the store channel, and recovery is a `Σ` that
  becomes empty (`obliterate-cuts-recovery`), with the adversary's ignorance
  surviving the operation because its observation did not change
  (`obliterate-ignorance`);
* rotation is an update to a `usable` predicate, so "no agent can use the old
  key" is a theorem with a Bool on the right (`rotate-forgets-old`), and the
  deleted Idris lemma now has a proved counterpart. It follows from the
  definition of `rotate`; its content is that the statement is now
  *expressible*, which the Idris modality could not manage, not that it is deep.

Two fixtures pin the refusals: `AdversaryKnows.agda` (asserting the two stores
are identical — refused, `2 != 1`) and `OldKeyStillUsable.agda` (asserting the
old key survives rotation — refused, `!= true`).

What this does **not** do is move E-1. A model of channels is not a model of
cryptography: that the store channel is the only one an attacker has, and that a
key which is not `usable` cannot decrypt, are assumptions (X-1), and E-1 stays
`OPEN`. The Idris module is unchanged — its typecheck status, its deleted lemma
and its comments now pointing here — because the theory belongs in Agda under
PROOF-POLICY §1 and the ABI belongs in Idris2.

== Reporting rules this repository follows

* No percentage, ever. Where a "completion" figure exists elsewhere in the
  tree it is a project-plan measure, not a proof measure, and it is not a grade.
* Every grade names its receipt: commit, prover, prover version, flags,
  sibling pin. §The receipts names the current receipt for the Agda modules and
  for the recheck legs, with the lineage of each.
* A receipt is invalidated by a change to a graded artefact, to its checker or
  to its pin, and is then re-earned by the next run, not carried forward.
* A receipt that is no longer current carries `state: superseded` (a newer
  receipt replaced it) or `state: regressed` (the source no longer checks), with
  the reason (PROOF-POLICY §8.4). These are receipt states, not status tokens,
  and neither receipt is deleted from the history.
* `AGDA-PENDING` is the correct correspondence state for a module committed but
  not yet checked. No row in this repository is in that state today: the five
  graded rows are `AGDA-VERIFIED` at the commit above, and each of their Rocq
  and Lean legs is `re-proved` and `RECONCILED`. No leg is `unavailable`:
  under §2 that route means a leg that cannot be built, and a hand re-proof was
  available for all ten.
* Grade counts appear only as the census at the top of this page: a count per
  rung, with the denominator and the `ungraded` rung in the same line.
